สิ่งที่ควรจำ แม้จะลืมรายละเอียดของแต่ละ topic ไปแล้ว

  1. LayerZero ส่งข้อความ ไม่ได้ถือเงินEndpointV2 ถือ 0 ส่วนเงินอยู่ใน OApp ที่เราเขียนเอง ความปลอดภัยของเงินจึงเป็นความรับผิดชอบของเราเกือบทั้งหมด
  2. DVN ตัวเดียว = key ดอกเดียวก็ mint ได้ไม่จำกัดdrill ปลอม mint ได้ 1,000,000 แล้วดูด lockbox จนหมด ส่วน path ที่ต้องผ่าน 2 DVN อิสระ การโจมตีเดียวกันถูกบล็อกด้วย LZ_ULN_Verifying
  3. อย่าพึ่ง default ของ endpointdefault บน testnet ทางการใช้ DVN ตัวเดียว ทั้ง messaging และ lzRead ต้องตั้ง DVN, pin library และใส่ optionalDVNCount = 255 เองทุก OApp
  4. config ฝั่งส่งกับฝั่งรับต้องตรงกันถ้าไม่ตรง message จะค้าง แก้ config ทีหลังก็ไม่ช่วย message ที่ค้างไปแล้ว ต้องให้ DVN ที่ขาดไป attest เอง
  5. gas ปลายทางต้องวัดจากเชนจริงตั้ง lzReceive ไว้ 100k แต่ใช้จริง 174k (Arbitrum Sepolia) และ 697k (Sepolia) และ forge จำลอง deploy ต่ำกว่าจริง 7.7 เท่า เพราะ Sepolia เปิด Glamsterdam
  6. นับ nonce จับการปลอมไม่ได้เสมอพอ nonce จริงตามทัน ตัวเลขก็ตรงกัน ต้อง audit ด้วย payload hash ทีละ nonce และเฝ้า invariant minted ≤ locked
  7. stablecoin ต้องมี control ตั้งแต่วันแรกrate limit, pause, blacklist (แยก role จาก owner) และ quarantine แทน revert เพราะ lzReceive ที่ revert ทำให้ message ค้างถาวร
  8. owner ต้องเป็น multisig และ config ต้องเป็น codeSafe 2-of-3 คุม OApp และ layerzero.config.ts เป็น source of truth ส่วน DevTools คำนวณ diff ให้ทุกครั้ง
  9. IBC กับ LayerZero ใช้คู่กันได้IBC (light client) ไปฝั่ง Cosmos และ LayerZero ทางการไปฝั่ง EVM ส่วน USDC ให้ใช้ของ issuer ไม่ต้อง bridge เอง
  10. infra ที่ไม่มีใครเฝ้าจะพังเงียบๆไม่มี relayer 14 วัน IBC client ก็หมดอายุทั้งสองฝั่ง ต้องมี relayer รันตลอดและมี alert ก่อนหมดอายุ

ส่วนที่ 1 · พื้นฐาน LayerZero (topic 1–8)
TOPIC 1

ปัญหา cross-chain และภาพรวม

อธิบายได้ว่า LayerZero เป็น messaging layer ไม่ใช่ bridge

  • "bridge" ที่แท้จริงคือ OApp ที่เราเขียนเอง (OFT/Adapter ทำหน้าที่ lock, mint และ burn)
  • Ronin, Wormhole และ Nomad จบเหมือนกันหมด: mint หรือถอนได้โดยไม่มีของจริงรองรับ
  • สิ่งที่ช่วยได้ทุกเคส: ผู้ยืนยันหลายรายที่อิสระต่อกัน, rate limit, invariant แบบ real-time และสวิตช์หยุดฉุกเฉิน
หลักฐาน: Endpoint ถือ 0 POTATO / 0 USDC ส่วน adapter ถือ 68.88 POTATO และ 852.5 USDC
TOPIC 2

Architecture V2

ไล่ lifecycle ได้: send → verify → commit → lzReceive

  • PacketSent → DVN verify → commitVerification → executor เรียก lzReceive
  • Executor ปลอม message ไม่ได้ ทำได้แค่ส่งช้าหรือไม่ส่ง (เป็นเรื่อง liveness)
  • relay ด้วยมือทุกขั้นช่วยให้เห็นว่าแต่ละ role ทำอะไร
หลักฐาน: event ครบ lifecycle 1/1/1 ทั้งบน anvil และ potato
TOPIC 3

Security model และ config

ออกแบบ DVN set, threshold และ confirmations สำหรับ stablecoin

  • DEMOWEAK (1 DVN) โดนปลอม mint ส่วน DEMOSAFE (2 DVN) ถูกบล็อก
  • DVN ต้องอิสระจริง คือคนละ key และคนละองค์กร ไม่ใช่แค่หลาย key ในองค์กรเดียว
  • config ไม่ตรงกัน → message ค้าง → ให้ DVN ที่ขาด attest เองแล้ว delivered ภายใน 3 วินาที
หลักฐาน: attacker ได้ 1,000,000 บน path 1 DVN และได้ 0 บน path 2 DVN
TOPIC 4

OApp บน testnet ทางการ

deploy OApp บน 2 testnet แล้วส่งข้อความข้ามเชน

  • forge จำลอง deploy ได้ 1.47M แต่ของจริงใช้ 11.39M (Glamsterdam/EIP-8037) จึงต้องใช้ --skip-simulation
  • ping แรก FAILED เพราะ gas ไม่พอ กู้ได้ด้วยการส่งเองด้วย gas ที่พอ แล้วแก้ต้นเหตุด้วยการกำหนด gas ต่อเชนปลายทาง
  • faucet ส่วนใหญ่บังคับว่าต้องมียอดบน mainnet เลยใช้ Google faucet แล้ว bridge ผ่าน Inbox ของ Arbitrum
หลักฐาน: ping ไปและกลับอัตโนมัติ 94 วินาทีและ 142 วินาที
TOPIC 5

OFT: token ข้ามเชน

เลือก OFT, OFTAdapter หรือ NativeOFTAdapter ได้

  • token ใหม่ใช้ OFT, token ที่มีอยู่แล้วใช้ OFTAdapter (lock/unlock) และเหรียญ native ใช้ NativeOFTAdapter
  • shared decimals ทำให้มีเศษ (dust) ค้างใน wallet ผู้ส่ง ไม่หายไปไหน
  • invariant: locked บน home = minted บนเชนอื่น (นับรวม message ที่ยังอยู่ระหว่างทาง)
หลักฐาน: ใช้ครบทั้งสามแบบใน topic 13/14 (ADR 0002/0003)
TOPIC 6

Stablecoin controls

rate limit, pause, blacklist และ supply invariant

  • blacklister เป็น role แยกจาก owner ตัว owner จึง blacklist เองไม่ได้
  • เงินที่ส่งมาให้ address ที่ถูก blacklist จะถูก quarantine แทนการ revert (revert = message ค้างตลอดไป)
  • contract upgrade ไม่ได้ จึงต้อง deploy v2: ปิดขาเข้าของ v1 แต่เปิดขาออกไว้ให้ผู้ใช้ถอนกลับมาเอง
หลักฐาน: unit test 15/15, release ให้ address ที่ยังถูก blacklist ไม่ได้
TOPIC 7

lzCompose และ lzRead

ออกแบบ compose และ read ให้ใช้กับงานจริงได้

  • composer ต้องรับเฉพาะ endpoint และ OFT ที่ไว้ใจ และถ้าล้มเหลวต้อง refund ไม่ใช่ revert
  • executor ต้องมี allowlist ไม่งั้น compose ปลอมจะถูก retry ไปเรื่อยๆ
  • default ของ lzRead ก็ใช้ read DVN ตัวเดียวเหมือนกัน จึงตั้ง LayerZero Labs + Horizen เอง
หลักฐาน: unit test จับ bug offset 108 → 76 ได้ก่อน deploy; lzRead ได้ผล 1 == 1 ใน 289 วินาที
TOPIC 8

Deploy, ops และ debugging

มี runbook สำหรับ deploy และรับมือเหตุการณ์

  • BlockedMessageLib หยุด path ได้ภายใน 14 วินาที โดยไม่ต้องมี pause ใน contract
  • ย้าย DVN แบบไม่ให้ message ค้าง: pause → setConfig ทั้งสองเชน → unpause (maintenance window 16 วินาที)
  • pin library, ย้าย owner และ delegate ไปที่ Safe 2-of-3 แล้ว wire ผ่าน DevTools
หลักฐาน: EOA ทำอะไรไม่ได้แล้ว, Safe ที่มีลายเซ็นเดียวได้ GS020, DevTools ตอบ "The OApp is wired"
ส่วนที่ 2 · เชื่อม potato-chain (topic 9–16)
TOPIC 9

ความพร้อมของ potato-chain

ยืนยันว่า LayerZero V2 ทำงานบน potato ได้

  • potato เป็น EVM ระดับ Prague และใช้ gas ใกล้เคียง anvil มาก (ต่างกันแค่ 12 gas)
  • block ละประมาณ 1.25 วินาที และ finality ทันที จึงตั้ง confirmations = 1 ได้
  • เช็คก่อนว่ามีอะไรใช้ port อยู่ แล้วค่อยย้ายของเรา อย่าปิดของคนอื่น
หลักฐาน: loopback ผ่านบน potato, gas 173,989 เทียบกับ 174,001 บน anvil
TOPIC 10

เชนคู่และ topology

เลือกเชนคู่, EID และ home chain ของแต่ละ asset

  • topology เก็บเป็น JSON ที่เดียว ทุก script อ่านจากไฟล์นี้
  • checker ต้องผ่าน negative test ด้วย: ใส่ค่าผิดแล้วต้องจับได้
  • anvil ที่ใช้ --state ยังมี state อยู่หลัง restart
หลักฐาน: topology ✅ 16/16 และจับค่าผิดได้ 2/2 จุด
TOPIC 11

Deploy protocol เอง

EndpointV2 และ ULN302 บนสองเชน พร้อม default config

  • script ต้อง idempotent: รันรอบสองต้องไม่มี tx (reused/ok)
  • อ่าน config กลับจากเชนเพื่อตรวจทุกครั้ง อย่าเชื่อแค่ log ของ script
  • OpenZeppelin v4 กับ v5 ชนกัน แก้ด้วย remapping ตาม context
หลักฐาน: wiring ✅ 12/12, nonce ตรงกันทั้งสองทาง
TOPIC 12

DVN และ Executor ของเราเอง

worker ส่ง message ให้อัตโนมัติ

  • แยก key ให้แต่ละ role และให้ DVN attest เฉพาะงานที่ถูก assign ให้ตัวเอง
  • worker ต้องตามงานที่ค้างระหว่างที่ปิดอยู่ได้ (restart test)
  • พิสูจน์ bug ด้วย repro ก่อน แล้วแก้ที่ต้นทางด้วย patch พร้อม regression test
หลักฐาน: end-to-end 6–11 วินาที, fillTransaction 22,490 → 46,330 หลัง patch
TOPIC 13

Bridge POTATO (native)

โอนไป-กลับโดย supply ยังถูกต้อง

  • WPOTATO precompile ไม่ใช่ WETH จริง (withdraw แค่ emit event) จึงเลือก NativeOFTAdapter
  • msg.value ต้องพอดีกับยอด ถ้าเกินแม้ 1 wei ได้ IncorrectMessageValue
  • ผู้รับที่รับ native ไม่ได้ทำให้เกิด CreditFailed ทดสอบใน unit test เพื่อไม่ให้ message ค้างบนเชน
หลักฐาน: locked 100 = minted 100 และ invariant ยังถูกต้องระหว่างที่มี message in-flight
TOPIC 14

Bridge USDC

bridge USDC ด้วย model ที่ถูก พร้อม controls

  • home ของ USDC คือเชนของ issuer ส่วนเชนอื่นเป็น OFT ที่ mint/burn
  • rate limit บล็อก 15,000 ได้โดย supply ไม่เปลี่ยน
  • message ที่มาถึงตอน pause จะรออยู่ แล้ว delivered หลัง unpause โดยไม่หาย
หลักฐาน: locked 599.5 = minted 599.5 และ delivered 23 วินาทีหลัง unpause
TOPIC 15

Frontend, indexer และ explorer

ผู้ใช้กด bridge และเห็นสถานะของ message

  • นาฬิกาของแต่ละเชนไม่ตรงกัน (anvil ช้า 157 วินาที) indexer จึงต้อง upsert แทนการพึ่งลำดับเวลา
  • เทียบยอดของ indexer กับ check-supply ให้ตรงกันก่อนจะเชื่อ UI
  • indexer ยังไม่รู้จัก event Quarantined จึงแสดงว่า "delivered" (ยังค้างเป็นงาน)
หลักฐาน: UI: sent → verified 1 วินาที → delivered 3 วินาที
TOPIC 16

IBC vs LayerZero และทางไป production

ตัดสินใจว่า asset ไหนใช้ IBC หรือ LayerZero

  • LayerZero ที่ self-host ไป production ไม่ได้ เพราะติด license LZBL-1.2 และเชนอื่นไม่รู้จัก endpoint ของเรา
  • IBC client หมดอายุทั้งสองฝั่ง กู้ด้วย recover-client ผ่าน gov แล้ว channel-0 ยังเป็นตัวเดิม
  • สคริปต์ gov ต้องรอ proposal id ใหม่ ไม่งั้นจะไปจับ proposal เก่าที่ผ่านไปแล้วและรายงานว่า "ผ่าน" ผิดๆ
หลักฐาน: potato proposal #3 และ gaia #1 ผ่าน, ibc smoke test ✅ 7/7

Drill: DEMOWEAK ถูกปลอม mint

ซ้อมเหตุการณ์จริงตั้งแต่ถูกโจมตีจนกู้คืน (playbook docs/runbooks/bridge-incident.md)

  1. key ของ DVN-A หลุดpath ที่มี DVN ตัวเดียว ปลอม message ได้ mint 1,000,000 DEMOWEAK.lz
  2. ดูด lockboxbridge 100 กลับไป ทำให้ lockbox ของจริงบน anvil เหลือ 100 → 0
  3. การโอนจริงค้างถาวรmessage ปลอมแย่ง nonce 2 ไป การโอนของผู้ใช้จึง POISONED
  4. ตรวจจับcheck-supply ขึ้น ❌ minted > locked และ audit ด้วย payload hash เจอ FORGED
  5. หยุดความเสียหายตั้ง BlockedMessageLib ทั้งสองเชนภายใน 14 วินาที
  6. อุดรูถอด DVN-A ออก ให้ v2 ต้องผ่าน B + C แล้วลอง key A อีกรอบได้ LZ_ULN_Verifying
  7. กู้คืนsnapshot สิทธิ์ของแต่ละคน treasury ชดเชย 103 แล้ว v2 ได้ locked 102 = minted 102

อะไรได้ผล

  • invariant minted ≤ locked จับได้ทันที
  • BlockedMessageLib ใช้ได้กับ OApp ที่ไม่มี pause
  • v2 แยก nonce space แต่ใช้ token เดิม ทำให้กู้คืนได้สะอาด

อะไรไม่ได้ผล (แก้แล้ว)

  • การนับ nonce ถูกหลอกเมื่อ nonce จริงตามทัน → เปลี่ยนเป็น audit ด้วย payload hash
  • worker บอกว่า "already delivered" ทั้งที่ message ค้าง → เปลี่ยนเป็น ALERT POISONED
  • 3 DEMOWEAK ค้างใน adapter v1 ถาวร เพราะไม่มีทางกู้

  • ติดต่อ LayerZero Labs เรื่อง chain integration ทางการ (P8)
  • หา DVN ≥ 2 รายที่อิสระต่อกันและรองรับ potato
  • enforced options ของ POTATO/USDC ยังเป็น 100k ต้องวัดใหม่บนเชนจริง
  • เพิ่ม pause และ rate limit ให้ PotatoNativeAdapter
  • audit contract และ config ของทุก path

ต้องทำ Operations และ IBC

  • alert real-time เมื่อเจอ FORGED/POISONED, invariant ผิด หรือ message ค้าง
  • relayer ≥ 2 operator และ alert ก่อน client หมดอายุ
  • IBC rate-limit middleware สำหรับ ICS-20
  • indexer ต้อง index event Quarantined
  • ทางกู้เหรียญที่ค้างใน adapter ที่ปิดไปแล้ว (ต้องออกแบบไม่ให้เป็นช่องโหว่ใหม่)

พร้อมแล้ว

  • potato เข้ากันได้กับ LayerZero (Prague, finality ทันที)
  • patch RPC 2 ตัวของ cosmos/evm
  • รูปแบบ control ของ stablecoin + unit test
  • check-supply + audit ด้วย payload hash
  • playbook incident ที่ซ้อมแล้ว, Safe + DevTools workflow
  • runbook กู้ IBC client (make ibc-recover)
